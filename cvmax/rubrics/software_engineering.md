# Program rubric: Software Engineering

Typical targets: backend, frontend, full-stack, mobile, QA automation, DevOps intern/junior.

What recruiters look for:
- Programming languages near the top, and only ones the candidate can be interviewed in (Google).
- GitHub or open-source contributions (Google calls this critical); competitive-programming profiles if
  ratings are strong.
- At least 2 projects, each linked, with the stack named and a result or scale (users, latency, test
  coverage, deployment) (Tech Interview Handbook).
- Experience beyond internships counts: open source, apps, hackathons (with placement), competitions.
- Measured technical impact: "improved response time by 15% by restructuring the API" (Google).
- Grouped skills: Languages | Frameworks | Databases | Tools/Cloud. GPA if 3.5/4.0 or above.

Common mistakes: two-column or graphic templates; content in headers/footers; listing technologies the
candidate cannot defend; vague projects ("built a website"); tutorial clones with no users, tests or
deployment; acronyms only (no "Amazon Web Services").

Format: Education -> Experience -> Projects -> Technical Skills (or Skills right under Education).
One page for interns. Header with GitHub and portfolio.

Example bullets (style reference only):
- Built a REST API in Go and PostgreSQL for a room-booking service used by 1,200 students; p95 latency
  under 120 ms at peak.
- Cut page load time of a React storefront by 38% by code-splitting routes and lazy-loading images.
- Wrote 140 unit and integration tests (pytest, GitHub Actions CI), raising coverage from 41% to 83%.
- Won 1st of 27 teams at a 48-hour hackathon with a Telegram bot for shelter locations (TypeScript).
