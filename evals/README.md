# Перевірка якості аналізу

Тут зібрані CV з відомими проблемами і те, що аналіз мусить на них помітити.

- `cases/` вигадані приклади, вони є в репозиторії.
- `private/` справжні CV. Ця папка не потрапляє в git: CV містять персональні дані.

Як працювати з пропуском, який знайшов юзер:
1. Додай CV у `private/` і JSON-кейс поруч (формат як у `cases/example_student.json`):
   `line_contains` це шматок рядка, `verdicts` це які вердикти вважаються правильними.
2. Запусти `python evals/run_evals.py` і переконайся, що новий кейс падає.
3. Зміни рубрику (`cvmax/rubrics/`) або промпт (`cvmax/prompts.py`).
4. Запусти знову: новий кейс має пройти, а старі не впасти.

Модель відповідає не завжди однаково, тому важливий кейс варто прогнати 2-3 рази.
Кожен запуск витрачає один запит до моделі на кейс.
